# Selecting a supported work step

The coordinating agent owns understanding, research, planning, arithmetic, file
selection and immutable acceptance checks. This runtime is a bounded code writer,
not a replacement for that agent or a whole-application development environment.

Read the target project's current instructions/task before selecting a route.
Coding-test and technical-interview work stays with the coordinating Codex task
end-to-end. Prose, translation, explanation, numerical judgment and exact-text
saves do not become coding tasks because their output has a file extension.
Unresolved purpose or unsupported edits/checks must be handed back explicitly.

For new supported product work, declare `task_category: product-development` and
the exact `generation_profile: huihui-qwen38-q6kl-v1`. Bound an exact Git revision
and existing paths for repo edits, or an empty candidate and up to eight exact
paths for new artifacts. Keep the full required context and check quality; do
not discard them to fit a model budget. Historical profile/profile-less fixtures retain their original meaning. The public
v2 execution entry requires the explicit current profile and does not execute old grants.

The default standalone flow is a reviewed packet → new bounded contract → explicit
operator approval → run → immutable checks → candidate evidence. In optional
PlzDo mode a reviewed parent marker supplies the one authority; it is not an
additional standalone approval. Never rename/reprepare/adopt to refund consumed
calls. Local model health/scope/identity errors stop rather than authorizing a
cloud retry. External calls need their own explicit permitted capability.

For a goal that needs new children after approval, select the explicit
[scoped-delegation protocol](scoped-delegation.md). Existing exact contracts do
not grow automatically. A valid scope lets the coordinator admit new bounded
children under the same root ledger; routine plan/implement/check transitions,
worker replacement and remaining in-scope retries do not require another human
conversation. Keep the original goal active until every success criterion is met.
Ask once for the specific missing scope/data/provider/budget decision, not once
per internal command. Report `can continue`, `AI review needed`, `user decision
needed`, or `blocked` with its actual reason; validation is not human approval.

Managed HTML observation requires the documented host browser transport, exact
generated-file preview, observation and shutdown evidence. Pending observation
is not success. An accepted candidate remains `not_applied`; original-target
application follows the target project's separate gate.

Scheduled execution is outside this public candidate. Existing private HN and
operational automations remain separate, under their original authority. Neither
package installation nor a personal computer creates scheduling/provider permission.

This guide is reusable text, not an installed global skill/hook. Installing this
package does not replace any user's existing agent instructions or automations.
